智语外呼：受控自主进化建议（2026-11-04）

更新：第一版已实现对话留存、反馈、候选生成、独立验证与封存测试、审核发布和回滚。
操作与实际能力边界以 docs/evolution-operations.txt 为准；下面保留更完整的后续设计方向。

赛题依据：本地赛题 PDF 第3页要求方向包括自动生成测试与对抗性模拟用户、规则评分和
LLM-as-Judge、失败聚类归因、提示词/话术/检索/工具策略优化、版本管理、回归和安全回滚。
原文为“鼓励探索”，不应误称为第5页列出的三项基础门槛之一。第6页把RSI进化有效性列为同分首要比较项。
第6页禁止硬编码评测答案和针对已知测试用例做特判。

建议第一版：离线分析对话 → 自动生成候选提示词 → 独立回归 → 人工审核发布 → 可回滚。
不要求本地训练大模型，现有文本模型 API 可承担模拟客户、失败分析和候选生成。
不在客户正在说话时进行优化，避免影响响应速度。

实施顺序：
1. 留存脱敏/合成会话、规则来源、Agent版本、工具调用、实际回写与错误、时延及成本。
   先核实语音历史是否持久化，现有业务结果落库不能代替全量对话日志。
2. 构建训练/开发/封存测试三份数据，按业务场景和意图划分，避免同一句的改写跨集合泄漏。
   覆盖多材料追问、改口、拒绝、身份不符、无依据、闲聊、工具失败与提示注入。
3. 固定基线版本运行；硬规则查身份隔离、禁止编造、写库授权和幂等；LLM裁判辅助评估表达。
   裁判分数不得替代关键规则断言；抽样人工核验裁判判断。
4. 对失败聚类区分 ASR、分类、知识缺失、状态管理、工具失败、表达问题。
   仅用开发数据自动提议分类提示词/示例/有依据的话术修改；缺业务依据则形成待补资料项。
   不允许模型从客户说法创造政策、额度、期限，不改身份校验、写库权限和回滚机制。
5. 在同一配置和独立验证集对比基线与候选；硬约束必须全部通过，主要质量指标提升，
   时延与调用成本不越预设上限；不达标自动拒绝。封存测试只在最终选择后评估，不反复用来调参。
6. 保存候选diff、日志、数据版本、模型版本、判分依据和失败用例；审核发布后保留旧版本，
   演示一键回滚。不宣称“越聊越聪明”，展示可复现实验的真实变化。

  提示词/Agent测试与多方案对比；根LICENSE为MIT。

成本控制：以文本模拟为主，只有入选方案再跑少量语音端到端样本；设置总调用次数和费用上限。
展示建议：基线回放 → 失败归因 → 候选差异 → 验证集前后指标 → 审核发布 → 回滚。
所有前后准确率、P50/P95和费用均须实测，禁止写演示用虚构提升数字。
