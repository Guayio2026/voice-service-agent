## 2. 补充探测：确认之前的复述没有被绕过

我担心"无待确认内容 → 建立待确认项"这步会变成"用户没听到内容就被要求确认"。新增 `scripts/probe_confirm_without_recital.py`，在 identity=verified、pending 为空、无未解决问题的状态下连说三次"确认登记"：

| 轮次 | 回复 | pending | 记录 | 含材料复述 |
|---|---|---|---|---|
| r1 `确认登记。` | 完整复述材料清单（含合成依据）+ "如已理解…请回复确认登记" | true | 0 | **是** |
| r2 `确认登记。` | 沟通结果已登记。… | false | 1 | 否 |
| r3 `确认登记。` | 沟通结果已登记，无需重复确认。 | false | 1 | 否 |

结论：**复述在前、写入在后，且重复确认不重复写入**。V023 第 1 轮之所以没有当场复述原文，是因为该例前置为 `pending_state=awaiting_confirmation`（场景设定为"上一轮已说明材料"），复述已在场景前置里发生过，属于用例设定而非产品跳过。

## 3. H019 转 FAIL：是新口径与旧断言冲突，不是缺陷

`H019` 前置 identity=verified、pending 为空、追问应答阶段。

```
r1 确认登记。      → 复述材料清单 + 请回复确认登记        step=confirmation  rec=0
r2 那就记"用户已了解"。→ 再次复述同一份材料清单            rec=0
```

v1 冻结时这条的断言写的是"第 1 轮 reply 明确说明**没有待确认内容**"，那是按旧行为（直接拒绝）写的。你本轮把 N6 改成"先查询并复述、建立待确认项"，产品就不再回答"没有待确认内容"了——**断言过时，行为符合新口径**。

它的两条硬断言仍然成立：
- 前两轮均无写入（records=0）✔
- 旧的"确认登记"没有被复用到新内容（r2 没有直接写）✔

有一处可以再确认口径：r2 用户要求记的是"用户已了解"，系统复述的却是材料清单原文，两边内容不一致。若"登记内容必须与复述内容逐字一致"是硬要求，这里需要再看一眼；若允许系统统一口径复述，就不用动。

按冻结纪律，我没有改这条用例，标记为 **v3 待修订（断言改为"先复述再要求确认"）**。
