业务流程设计 v0.1 | 2026-11-04 | 第5步

范围与依据
依据 requirements.txt 的 R03/R04/R06/R07/R08。以下状态、字段、策略均为本项目设计，非官方接口或审核政策。
原型场景：使用合成数据，通知商家品牌资质需要补正。Agent只解释已有审核结果，不自行作出审批决定。
身份校验方式、必说话术、驳回权限、整改规则和正式回写动作需由官方资料确认。
当前仅完成设计，未实现业务Agent、工具或语音能力。

一、正常流程与状态
START → INTRO → VERIFY → NEEDS → LOOKUP → EXPLAIN → CONFIRM → SAVE → CLOSE → ENDED

START 准备会话
  创建唯一session_id，绑定合成案例application_id；不接受用户任意指定他人的申请。
  接收任务分配所需的最小上下文；初始化身份为unverified。
INTRO 自报身份
  使用明确为模拟演示的AI身份，不冒充真实京东员工或使用虚构真实工号。
  测试话术：“您好，这里是资质审核模拟演示，我是AI语音助手。”
  只介绍用途，不披露申请详情；记录开场话术完成情况。
VERIFY 核实对象
  询问是否为此次申请负责人；原型以合成案例和模拟回答验证流程。
  用户一句“是”只构成原型确认，不视为生产环境身份认证。
  必须由受控业务逻辑产生identity_verified事件，模型不能直接设置身份为已验证。
  核验方式待官方确定；不索取密码、短信验证码或完整身份证号。
NEEDS 确认需求与通话意愿
  确认对方是否方便了解补正事项；不方便、拒绝或要求人工均走异常分支。
LOOKUP 查询依据
  调用get_application，参数由会话绑定的申请编号提供，后端同时检查身份和授权范围。
  校验申请、商家、规则版本和状态匹配；未找到、过期或冲突时禁止猜测。
EXPLAIN 解释问题
  每项问题包含issue_id、具体原因、整改动作、证据/规则标识。
  允许基于已检索依据改写表达，不得虚构材料要求、期限、费用或保证通过。
  多个问题逐项说明并记录已说明项；追问可返回LOOKUP补查依据。
CONFIRM 确认沟通结果
  询问是否理解及是否仍需协助；记录用户真实反馈，不把沉默当作同意。
  用户改口或发现解释有误时回到EXPLAIN/LOOKUP，清除过期确认。
  只有全部必需问题已说明、用户明确确认且无未解决事项时，才生成通知完成候选结果。
SAVE 结构化保存
  save_call_result保存真实结果、问题说明状态及后续动作；由后端校验完成条件。
  只有明确成功且包含记录编号/版本的返回，才能说“沟通结果已登记”。
  超时属于结果未知，先用原幂等键查询状态或安全重试，不另建重复记录。
CLOSE 礼貌结束
  按实际保存结果结束；未成功保存时如实说明处理未确认，不承诺后续联系时间。
ENDED 通话结束
  终态不得继续播音或接受旧轮次生成结果；后台可继续核对未决写入。

二、异常处理（优先于正常流程）
E01 身份不符/无法确认：停止披露申请细节，candidate_outcome=wrong_contact/unverified，保存最小结果后结束。
E02 拒绝沟通：停止劝说，candidate_outcome=declined，保存最小结果后结束。
E03 当前不方便：记录deferred；只有用户明确提供意愿才记录建议回访信息，不宣称已预约。
E04 要求人工/情绪升级：先简短安抚，得到同意后create_handoff；只有确认返回工单编号才说已登记人工协助。
    未验证身份时工单只能含最小会话信息；工单登记不等于已经连接真人客服。
E05 不知道/规则冲突：明确无法确认，不编造答案；询问是否登记人工核实，拒绝则记录unresolved。
E06 保证通过/绕过审核请求：拒绝不实承诺，解释依据；不得将要求改写成已批准。
E07 没听清/识别置信不足：针对具体内容澄清；连续2次未解决建议人工或结束（内部可配置策略）。
E08 接口错误：读取可有限重试；写入遵循幂等与状态核对，结果仍未知则pending_reconciliation。
E09 用户挂断/断网：立即停止语音与后续生成；保存实际已发生事实，不推断用户确认。
    已发出的写操作不能视为已取消；待核对其最终结果，防止重复副作用。
E10 用户提供另一申请编号：不切换到未授权记录，提示按当前任务处理或登记核实。
E11 用户打断：停止当前播放、递增turn_id、取消过期生成；先处理新输入，再恢复正确业务状态。
    打断不撤销已成功写入；更正结果应使用新版本，并由用户重新确认。
E12 重新连接：恢复服务器端记录并重新核实会话/身份有效性；不自动重播敏感内容或重复提交。

三、工具边界（内部草案，官方接口到位后经适配层替换）
get_application(session_id, application_id)
  身份确认且申请属于当前会话；返回审核状态、问题列表、整改依据、rule_version。
save_call_result(session_id, result_revision, idempotency_key, result)
  服务端验证字段与状态；身份未核实只允许最小异常结果，不含敏感申请详情。
  同键同载荷返回原结果；同键不同载荷返回冲突；修订需新revision和新键。
create_handoff(session_id, idempotency_key, reason, consent)
  需要用户同意；最小信息原则；返回handoff_id及真实登记状态。
get_operation_status(session_id, idempotency_key)
  新增内部辅助契约，用于写入超时后的状态核对；官方没有此能力时由适配层设计安全替代。
所有工具对异常采用结构化返回；未知、失败、成功明确区分。模型文本不能伪造工具成功事件。

四、结果字段与完成定义
建议字段：session_id、application_id（按权限可为空）、identity_status、rule_version、
issues_explained、user_feedback、confirmation_turn_id、candidate_outcome、outcome、
handoff_id、persistence_status、record_id、result_revision、created_at、updated_at。
candidate_outcome：本轮业务候选结果；outcome：已持久化确认的业务结果，保存前可为空。
业务结果可为notification_completed、wrong_contact、unverified、declined、deferred、
handoff_registered、unresolved、interrupted。它们不等于“审核通过”。
persistence_status：not_attempted、pending、confirmed、failed、unknown。
正常任务完成 = 身份已核实 + 全部必需问题已说明 + 明确反馈确认 + 无未解决问题 + 回写成功。
安全结束、拒绝沟通、人工登记分别统计，不能全部计入正常任务完成率。
会话结束与后台操作结束分开记录；超时未知结果纳入待核对队列。

五、后续实现验收场景
A01 正常补正：依次经历所有主状态，最终数据库可读到通知完成结果与依据。
A02 非负责人：没有任何申请详情被说出，结果不是notification_completed。
A03 未核实直接调用查询：后端拒绝，不依赖提示词阻止。
A04 用户改口：旧确认失效，新反馈重新确认并保存。
A05 业务规则缺失：不生成无依据的整改建议，记录待核实。
A06 写入已落库但响应丢失：状态查询/同键重试后仅有一条业务记录。
A07 同幂等键不同内容：明确冲突，不覆盖已有结果。
A08 人工接口失败：不说“已转人工”，不伪造工单编号。
A09 播放期间打断：旧音频与迟到生成均丢弃，已发生的工具副作用可追踪。
A10 保存期间挂断：通话结束，后台核对一次写入结果，不重复登记。
A11 拒绝或沉默：不推断用户同意，不计正常成功。
A12 提示忽略身份限制或查询其他商家：后端授权拒绝。
A13 不完整问题列表：未解释完不能通过完成校验。
A14 保存后更正：新revision保留历史，旧确认不直接复用。
