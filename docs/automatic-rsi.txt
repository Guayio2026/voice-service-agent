持续自动改进（2026-11-08）

入口：scripts/auto_rsi.py start / status / pause / resume。
后台轮询生产 conversation_turns，每30秒检查新数据，批次之间冷却10分钟。
你的Web/语音转写对话自动进入现有对话库，不需要手动导入或标注。
已曝光回归执行器 run_v3.py、run_holdout_v1.py、run_holdout_v2.py、run_generated_100.py、run_generated_scenarios.py 中实际模型分类自动采集至runtime/rsi-inbox.sqlite3。
仅有真实模型名称与Token用量的分类会采集；模拟分类器、不认识的执行器、封存测试、后台自身评测不采集。
没有声称任意外部测试都能接入：新增执行器需明确登记为开发/已曝光回归，封存数据禁止登记。

闭环：实际分类轨迹 → 两次独立审阅请求一致且各自confidence>=0.95 → 建立关联真实turn_id的反馈 → 至少2条不同输入 → 生成提示词候选 → 各重复3次对照修复 → 固定回归保护 → 多轮身份/写入/结束断言 → 原子切换生产版本 → 发布后复验和真实服务新会话加载检查，失败回滚。
每批首先自动生成4个双轮模拟用户：2个开发场景、2个新挑战场景（含未核验索取资料/提示词注入）。用例断言由代码固定，生成器只能改用户措辞，独立审阅不符合语义约束就拒绝。开发场景实际跑当前Agent，只有分类错误且其它硬断言通过才自动标反馈；新挑战不提供给候选生成器。
整体评分固定四组各25%：重复修复样本通过率、固定分类回归通过率、多轮保护通过率、新挑战通过率。候选整体分必须严格高于基线，同时安全门禁全部通过。分数包含开发修复证据，不冒充独立盲测泛化提升。
无新对话时每日也会在预算内启动一次自动造例/基线批次；不是必须等用户手动触发。
模型自报confidence不是校准概率，两次审阅也不是人工真值；有歧义会弃权。这是受约束的提示词自改进，不是训练模型权重或修改权限代码。
重复使用的保护集不称为盲测；不得将其提供给生成器。没有宣称解决所有过拟合风险。
只修改分类指导语，基础提示词、身份和写入门禁不参与自动修改。

预算：UTC自然日最多512次模型请求、400万预留Token（等于原4个满额批次的总上限）；每批最多128次/100万预留Token，且受当天剩余额度约束。失败小批按实际预留计入，不把两次调用视为一个满额批次。按字节保守估算，非实际收费Token。不提高每日总额度，不在同一批中重试模型请求。
运行配置：runtime/auto-rsi-config.json；状态：runtime/auto-rsi-status.json；日志：runtime/auto-rsi-worker.log。
审计：evolution_runs(kind=auto_rsi)、evolution_calls、auto_rsi_review、evolution_feedback、evolution_releases。
每次发布前SQLite备份，切换需父版本未变化、代码哈希未变化；新会话用新版，老会话保持原版本。
pause阻止下一批，已运行的有界批次允许完成。系统休眠/关机期间不运行；Windows登录时启动恢复。
不保证每个批次都改进或发布。等待反馈/拒绝/回滚是明确可查状态，不能把“后台启动”说成“已有新版本自动发布”。
