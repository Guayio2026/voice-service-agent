## 3. 新回归 N9（P1）：告别与撤销被做成互斥信号

- 最小复现
  - `V013 r1`：`不办了，别登记。`（本轮 v2）
    - 实际：`好的，已取消这次待确认的登记，不会保存。您可以继续提问。`，`step=availability`，三轮都不结束
    - 上一轮：能结束（旧代码 `stop` 里含"别登记"）
  - `H016 r1`：`先这样吧，不用记。`（v1）
    - 实际：同上，`step=availability`
    - 预期：`session_status == ended`
- 根因（`src/business_agent.py:235-237`）
  ```python
  stop = re.search(r'不想说了|不想聊|不听了|不需要这个服务|别再打|不方便说|等我问完再打|(?:我)?挂了|让他自己打过来', text)
  cancel_write = re.search(r'(?:不用|不要|别|取消|撤销|先别).{0,8}(?:记|登记|记录|保存|写入)|…', text)
  if is_farewell(text) or phrase == '不用了' or stop or (not cancel_write and any(is_farewell(c) and …)):
  ```
  两处叠加：
  1. `not cancel_write` 把"告别分句"整条否决——只要句子里有"不用记/别登记"，即便前半句是"先这样吧"也不结束（H016）。
  2. "别登记"从 `stop` 移到了 `cancel_write`，"不办了"又不在任何告别词表里（`is_farewell` 只认 再见/拜拜/先这样/就这样吧/挂了），于是 V013 两个信号都落空。
- 为什么算回归：上一轮 H016 是 PASS、V013 是 PASS，本轮双双转 FAIL，属于"修 N5 时把 N4 的判定条件挤掉"。
- 建议（顺序很关键）：**结束优先级高于撤销**。
  1. 先判结束：命中告别/放弃语 → 结束，并在结束语里说明"本次不会写入"（避免用户以为还有待确认）。
  2. 只有"纯撤销"（无任何结束信号）才走 `cancel_write` → 保持会话。
  3. 告别分句判定改成 `search` 词表并补：`不办了|不做了|不用了|算了|就到这儿|那算了`；去掉 `not cancel_write` 这个否决条件。
- 验收：V013、H016 第 1 轮即 `ended` 且全程 `ended`；同时 V012 第 1 轮**不得**结束（纯撤销），V011/V015 不回归。

## 4. 遗留与口径

**N6 残余（P1，V023）**：`确认登记？`（被判疑问，合规）→ `确认登记。` → 仍回"目前没有待确认的登记内容，尚未保存"，记录 0。
本轮只修了"库内已有记录"那一支（V021 已通过），"无记录、无 pending"那一支没修：应当直接复述待登记内容并生成 `pending`，而不是让用户自己想"先说明处理意向"。这与上轮报告 N6 建议的第 2 支完全一致，直接按建议补即可。

**口径差异（V012，与 H022 同源）**：r3 `那你帮我重新记一条：材料已了解。` → `还有未解决的问题，不能登记通知完成。请继续说明或请求人工核实；问题确实解决后请明确回复"问题已解决"`。这是"未核实问题不得登记"的更严设计，v1 的 H022 上轮已判为口径而非缺陷，本轮 V012 同判，不新增缺陷编号。
