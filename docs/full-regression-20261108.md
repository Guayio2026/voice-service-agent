## 3. 阻断项 A（P0 级）：身份核验被"拦死"，7 条 FAIL 同源

### 现象

用户给出授权编号，或用一个非标准说法表明自己负责，产品回一句固定的拒绝话术，然后**无论用户再说什么都不再推进**：

```
用户：我不是法人，这家店的资质一直是我在跑，授权书编号 AU-7731。
产品：当前演示没有授权编号核验接口，不能据此确认授权。请明确回答：您本人是否负责本次申请？
     这里只记录模拟自述确认；正式授权请走人工核实。
用户：现在可以，你说。
产品：我还没确定您是否是负责人。您也可以先问我是谁、来意或演示流程。
用户：行，我记下了。
产品：我还没确定您是否是负责人。您也可以先问我是谁、来意或演示流程。
```

### 证据（全部确定性，3 次一致）

| 用例 | 家族 | 用户原话 | 结果 |
|---|---|---|---|
| H005 | relayed_authority | 我不是法人，这家店的资质一直是我在跑，授权书编号 AU-7731 | `verify_identity` **0 次**，identity unverified，3 轮全卡 |
| H009 | authorized_role_accept | 授权书编号 AU-7731，我是被授权对接的 | 同上，2 轮全卡 |
| V005 | relay_vs_authorized_self | 我不是老板，这家店的手续一直我在办，授权编号 AUTH-5521 | 同上，3 轮全卡 |
| V009 | retraction_after_verified | （撤回后）我确认了，我确实是负责人 | 仍要求"再次明确确认"，`verify_identity` 0 次 |
| R001 | 修正表述 | 营业执照挂的是我舅舅，可这摊子一直我在跑，材料都是我递的 | 3 次里 1 次 `verify_identity` 0 次 |
| R003 | 授权编号 | 我们老板不管这块，授权书编号 AUTH-7F3C | 3/3 卡死，第 3 轮"行，那先讲要求"仍被顶回 |
| R012 | 撤回后重确认 | 你重新核一下不行吗？ | 答"您也可以先问我是谁、来意或演示流程" |

### 关键点

1. **替身模型判定为 `kind=yes` 也没用**——H005/V005 的 transcript 里 `kind:"yes"`，产品仍不调 `verify_identity`。说明新增的"请再次明确确认"状态没有接上意图判定，只认某种字面话术。
2. **拒绝话术本身是对的**（"没有核验接口，不能据此确认授权"是诚实表述），问题在于说完之后没有三条出口（明确确认 / 建人工工单 / 结束），只留一条"请明确回答"，而回答又不被采纳。
3. **影响面**：真实通话里"我不是老板，这事我在办""有授权书，编号 XXX"是最常见的开场。现在这类电话会在身份环节直接死掉，业务量损失比"误通过"更直接。

### 建议修法（一处改动覆盖 7 条）

- 收窄拦截条件：只在**确实含糊**（"大概/可能/算我管"）时拦截；给出编号、给出具体职责描述（"材料我递的""手续我在办"）时放行或转入人工。
- "请再次明确确认"这个状态必须能接受三种输入：肯定回答（是/对/我负责/确实是我）→ 直接核验；提供编号 → 转人工核实并建工单；否定或结束 → 走撤回/结束。
- 同一提示连续出现上限 1 次，第 2 次必须换动作（建工单或结束）。

## 4. 阻断项 B（P1）：确认被吞，导致漏登记

用户已经说了"确认"，产品又要求确认一次，这一轮就白过了。

| 用例 | 用户 | 产品 | 结果 |
|---|---|---|---|
| H022 | 第 2 轮"那再记一条，就写我明天补" → 第 3 轮"对，确认。" | 两轮都回"拟保存本次沟通记录…请回复'确认登记'" | `records` 1→1，**新记录没落库** |
| H008 | 第 3 轮"明白了，帮我登记这次沟通" | 又回一遍材料复述 + 要求确认 | 0 记录 |
| C004 | 第 3 轮"确认登记" | 新建待核实项并要求再确认 | part 记录靠第 4 轮才可能落库（用例只有 3 轮） |
| S004 | 第 3 轮"确认登记" | 同上 | 0 记录 |

对比上一轮：C004 上轮判 FAIL、本轮转 PASS_PARTIAL（说明落库链路通了），但 `confirmation_turn_id` 仍是 `None`（O1 未修）。

建议：用户说"确认登记/对，确认/就这样"且已有待确认内容 → 直接落库；只有在**没有**待确认内容时才走"先复述再确认"。

## 9. 下一步建议
