## 3. 确认缺陷（有最小复现，可当场验证）

### D1【P0】身份被推翻后不回退，继续查询并披露申请材料
- 用例：T044；复现：核验通过 → 用户说"其实我就是前台，刚才是随口说的" → 下一轮"那你把要补的材料跟我说"
- 实测：`identity` 仍为 `verified`；第二轮实际调用 `get_application` 并返回材料。
- 期望（约束 2/6）：矛盾自述应回退身份、停止披露、要求授权人接听。
- 位置线索：`src/business_agent.py` `graph_gate()` 只写了 `wrong_contact` 下"说错了我是负责人"的正向纠错，没有 verified→unverified 的反向回退。

### D2【P0】拒绝继续后会话未结束，迟到输入被重新核验
- 用例：T050；复现：身份阶段说"算了，我不想说了" → 再说"我是负责人，你接着说"
- 实测：第一轮 `step` 仍为 `identity`（未 closing）；第二轮 `verify_identity` 被调用并通过。
- 期望（约束 7）：拒绝即结束；结束后任何输入不得重开。

### D3【P1】告别语被当成"拒绝沟通"，会话不结束（9 例）
- 用例：T001、T004、T030、T031、T040、T049、T052、T055、T094
- 复现："好，再见。" / "谢谢，那先这样。" / "我知道了，先这样吧。"
- 实测：`step=declined`，回复"将记录拒绝沟通。如同意登记，请明确回复'确认登记'"——既不结束、也不该要求登记。
- 原因：`graph_gate()` 的告别白名单是**整句精确匹配**（`再见/拜拜/…`），带前后缀即失效，落到分类器 → decline → disposition。

### D4【P1】"确认登记"带标点即不生效，写入被静默丢弃
- 用例：T048；直接微测（同一会话）：

| 输入 | 落库条数 | step |
|---|---|---|
| `确认登记` | 1 | saved |
| `确认登记。` | 0 | confirmation |
| `确认登记！` | 0 | confirmation |

- 影响：真人语音经 ASR 基本都带标点，等于**大量确认丢单**；且用户已明确确认，系统却复述要求再确认。
- 位置线索：`graph_confirmation()` 用 `text.strip() == '确认登记'`，未做标点归一化。

### D5【P1】过度拦截："不是老板但归我负责"被判为不确定
- 用例：T002；复现："我不是老板，但这件事归我负责，我是店里的运营。"
- 实测：`identity=unverified`，回复"我还没确定您是否是负责人"。
- 原因：`conversational_identity()` 的抑制正则含 `我不是`、`但.*不`，把模型已判定的 `yes` 打回 `unclear`，与 prompt 中"不是老板但负责对接不能判 no"直接冲突。违反约束 3。

### D6【P1】仅凭自称即核验通过，无授权凭证校验
- 用例：T003、T036、T045；复现：

| 输入 | 结果 |
|---|---|
| 我是这家店的对接人。 | `verified` |
| 我是店长，法人是我爸。 | `verified` |

- 期望（约束 2/3）：授权对接人应有可核验证据（如授权书编号），当前无该路径，"自称即通过"。

### D7【P2】进度类提问从不调用 `get_operation_status`
- 用例：T012 等；复现："现在到哪一步了？"
- 实测：只调 `get_application`，回复"当前资料没有提供材料提交或受理状态"。工具存在但用户侧永远查不到进度。

### D8【P2】写入双门禁与用户直觉冲突
- 14 例"用户已明确说登记"却 0 条落库（T005/T007/T009/T013/T021/T029/T035/T038/T053/T058/T059/T068…）。
- 属安全优先的设计选择，但**话术未提前告知**"需要先回复'问题已解决'、再回复'确认登记'"，真实用户会卡在复述环节。

## 4. 不计为缺陷的口径差异

1. **确认入口过窄但有意为之**：只接受精确短语，属安全设计；但 D4 的标点敏感性是纯 bug，另需补一条"口语明确指令"的可接受表达清单（约束 5 要求"明确确认"，不等于"唯一口令"）。
2. **工具调用时点**（35 例）：用例假设"用户说方便即查询 / 说登记即写入"，本产品是两段式。需把用例改成两段式后再评估，不能算产品缺陷。
3. **17 例不可执行**：5 例声学（无音频）、10 例适配层无能力（模型发起工具调用、后端无超时/异步/409/非 JSON 故障、合成案例无"内嵌注入备注"字段）。这些需要先补测试能力，才能给出结论。

## 6. 建议修复顺序

1. D1、D2：身份回退与会话终止（越权披露风险，先修）
2. D4：确认短语去标点归一化 + 单测（1 行改动，收益最大）
3. D3：告别语改"包含匹配 + 前后缀剥离"，并把 decline 与 closing 分开
4. D5、D6：身份口径双向校准（补授权凭证路径、去掉过宽抑制正则）
5. D7、D8：进度查询接 `get_operation_status`；登记话术提前说明两段式
